The gap nobody names

The preview is unsigned. The capture is signed. Nothing links them.

Camera / SBI device
unsigned preview →
Liveness check passes on face A
signed capture →
Registration packet stores face B
  • Capture swap: whoever controls the preview can pass liveness with one face and enrol another.
  • Android: the client never sees preview frames at all; the device app shows the stream and returns only the signed capture.
  • Injected video (OBS, deepfake pipelines) is outside ISO/IEC 30107. Insiders can log in with a supervisor's photo.
  • No audit trail: a client-side pass/fail cannot be re-checked by the server later or re-scored with a better model.

What is different

Each idea is built and tested. None is claimed beyond what the claim sheet allows.

Capture binding

Four locks before any accept: nonce echoed in the device-signed capture, frame hash chain, identity continuity, time. Works on unmodified SBI.

Evidence, not a verdict

A signed JWS in the face BIR. One command re-verifies it; a newer model can re-score stored crops. Merkle transparency log.

Cues that fail differently

Passive, moiré, flash reflection (20.7-bit random colour code), scene, stereo. Each abstains when the station lacks the hardware.

Injection defence

Device identity chain, OS camera registrations (OBS found via DirectShow), JPEG stream fingerprint. Not a renamed-driver defence.

Inclusion by design

Blink, pulse and pupil reflex only ever vote for life. Hindi, icons, speech, accessibility profiles, infant mode, dual-control exceptions.

An SBI proposal

An optional Liveness Profile (signed preview, signed light log, signed burst) with a runnable reference device. Our own draft; not yet posted to MOSIP.

What is verified, and what is not

No real attack corpus exists, so no APCER or BPCER is claimed. Zero failures in 60 attacks would still allow a true rate near 6%.

Verified (one command each)

  • 703 automated tests pass (20 skipped on a fresh clone: no models)
  • Flash code: 1,679,616 sequences = 20.7 bits
  • At most 3 colour changes a second, 900 sequences
  • Insider signal: 6 in 40 at 2% gives z ≈ 5.87
  • Transparency log matches the CT test vectors
  • Each capture-swap attack is a failing test

Not done, not claimed

  • No error rate on real attacks; thresholds provisional
  • Not run on a device, a phone or a certified SBI device
  • Desktop app is a scaffold, not the Registration Client
  • No user has tried the screens; Hindi checked by the author only
  • Flash, stereo, scene cues: synthetic data and fakes only

We attacked ourselves. On synthetic screen replays with the passive model assumed fooled and no flash light, the fusion accepted 4 of 85 display pitches; with the flash cue, 0. Logged as R-03 with R-01 (moiré blind pitches); the fix (an accept needs a flash or stereo vote, else a challenge) is on for operators and supervisors, and not for residents.
